# FalsifyAI M5 guide

M5 runs the verified scientific pipeline once and shows the result in a local instrument screen. It does not add a scientific stage.

## Run locally

From the repository root, with the package installed:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m pytest
uvicorn app.main:app --app-dir backend --env-file .env --reload --port 8010
```

The application module is `app.main:app`. The file is `backend/app/main.py`.

In another terminal, start the screen on its own. It does not launch or wait for the API:

```powershell
cd frontend
npm install
npm run dev
```

`frontend/.env.development` sets `VITE_API_BASE_URL=http://127.0.0.1:8010`. The browser calls that origin directly. Vite does not proxy the API. Do not put an API key in any `VITE_` variable.

Development CORS allows only:

- `http://localhost:5173`
- `http://127.0.0.1:5173`

It does not allow every origin. The Meta API key stays in the backend environment. The frontend has no key.

## Try a hypothesis

`POST /api/v1/run` accepts `hypothesis`, `mode` (`stub` or `live`), and `reasoning_profile` (`economy` or `balanced`). Both defaults are the offline choice: stub and economy. Live mode does not fall back to the stub.

`GET /api/v1/examples` returns the pendulum claim, the vague field claim, and the labeled synthetic quantitative claim.

A blocked simulation is a scientific state. The run continues to the experiment designer and the judge. `scientifically_blocked` means the falsifier is not yet finite. `failed` means the pipeline stopped on a system or validation error.

`GET /health` reports milestone `M5`.

A manual live run can keep sanitized checkpoints in `tmp/live_run_checkpoint.json`. That directory stays gitignored. `python scripts/live_m5_resume.py --from critic` continues from a validated checkpoint and does not repeat the parser call. It is not part of pytest.
